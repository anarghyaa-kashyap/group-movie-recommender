# Deviation Log — SRS / SAD / Test Plan vs. Implementation

Required by Deliverables Part‑2 (Sprint‑1 item i): deviations must be documented and explained in the final demo.

| # | Document & item | What the document says | What was built | Why |
|---|---|---|---|---|
| D‑01 | SRS FR‑10, BR‑06, §2.5 | Fixed, configurable weights for compatibility, public rating and history, selected by validation | Configurable weights (`app/recommender.py · Weights`) **plus** a per‑group Thompson‑sampling Bayesian linear bandit for the history term | A group produces one reward per movie night; a bandit learns gradually from few data points and keeps learning strictly per group. Weights were chosen by a validation grid on the IMDb catalogue (`scripts/evaluate.py`, validation seed 1, separate from the reported seed 7): compatibility/rating 0.4/0.6 → **0.8/0.2**, history 0.3 → **0.05**. A history weight of 0.3 lowered NDCG@10 (0.58 vs 0.71); the bandit's gain at 0.05 is small (0.708 vs 0.701 with no history) |
| D‑02 | SRS FR‑12, Use Case "Rate Recommendation" | Members rate a recommended movie | The group first marks which recommended movie it **watched**; each member then rates that movie 1–5 | Only a watched movie gives a meaningful rating; unwatched list items are not treated as dislikes (they may simply have been seen before) |
| D‑03 | Use Case diagram, actor "Group Creator → Start Recommendation Session" | Only the creator starts a session | Any group member can start a session | SRS §2.3 states the creator has no separate privileges; implementation follows the SRS |
| D‑04 | SRS §1.4, Workflow Plan model note | Description embeddings with sentence‑transformers (all‑MiniLM‑L6‑v2) | TF‑IDF description vectors + genre vectors | Keeps the Docker image small (~150 MB vs >1 GB with PyTorch) and ranking well inside NFR‑01; the embedding function is isolated in `build_features` so it can be swapped |
| D‑05 | SRS TBD‑01, Workflow Plan dataset | The Movies Dataset (Kaggle), 10 000 most‑voted titles | **IMDb movies 2000–2020**, 5 487 titles (every title ≥ 10 000 votes), bundled directly as `data/movies.csv`: `original_title` → title (the raw export's `title` column held Italian release titles), `genre` → pipe‑separated genres, `description` → overview, `avg_vote` (IMDb, 0–10) → rating, `votes` → vote count. The one‑time conversion from the raw IMDb export is already done; the raw file and conversion script are not kept in the repo | Replaces the 72‑title synthetic demo catalogue. The file is bundled in the repo, so CI and Docker need no download credentials. Only films from 2000–2020 are covered |
| D‑06 | SRS NFR‑06, Test Plan TC‑EVAL‑01 | Offline evaluation on held‑out MovieLens ratings | Offline simulation on the **real IMDb catalogue** (`scripts/evaluate.py`): 30 simulated groups of 3–5 members × 8 sessions. A member's enjoyment = 65 % genre taste + 35 % IMDb rating; votes reflect tonight's mood (taste + session noise), the rating after watching reflects stable taste. NDCG@10 + reward per session vs rating‑only and preference‑only baselines | The IMDb export has no per‑user ratings, so members are simulated; protocol and metrics are as planned. Result (seed 7): hybrid **0.688**, preference‑only 0.622, rating‑only 0.554 (`docs/evaluation_results.json`) |
| D‑07 | Test Plan §3–4 and §7, test‑case sheet TC‑19/TC‑20 | NFR numbering: NFR‑03 Auth, NFR‑04 Privacy, NFR‑05 Usability, NFR‑06 Modularity, NFR‑07 Quality | Code, backlog and traceability use the **SRS numbering**: NFR‑03 Privacy, NFR‑04 Usability, NFR‑05 Maintainability, NFR‑06 Recommendation quality, NFR‑07 Robustness | The Test Plan was written against an earlier NFR list. Mapping: TP NFR‑03/04 → SRS NFR‑03 + SR‑01…06; TP NFR‑05 → SRS NFR‑04; TP NFR‑06 → SRS NFR‑05; TP NFR‑07 → SRS NFR‑06. SRS NFR‑07 (robustness) had no test case → added `test_nfr07_missing_rating_and_description_do_not_crash` |
| D‑08 | SRS SR‑05 / §3.4 HTTPS | HTTPS for deployed system | App serves HTTP inside the cluster; HTTPS is terminated at the ingress/load balancer in a real deployment | Local Minikube/kind demo has no certificate; noted as deployment configuration, not code |
| D‑09 | SRS TBD‑05 | Rule for members who leave / do not submit | Session participants are frozen when the session starts; a member who joins later waits for the next session | Simplest rule that keeps FR‑07 (wait for all participants) deterministic |
| D‑10 | Test Plan §8 test frameworks | PyTest or Jest; Locust/Postman for load | PyTest for everything; load test is `tests/test_nonfunctional.py::test_tc17` (20 timed runs against a generated 10 000‑title catalogue, the NFR‑01 upper bound) | Single toolchain; same pass criterion (≥95/100 under 3 s). Measured p95 well under 3 s on the 10 000‑title synthetic catalogue; the real 5 487‑title IMDb catalogue is faster still |
